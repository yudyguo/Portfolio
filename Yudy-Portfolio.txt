PROJECT 1: Design Landing page data panel of WeChat Official Accounts

WeChat Official Account
A platform for publishing content and providing services within the WeChat app.

My Role
Abstract core data from user research, focusing on potential user needs.

Background
The Landing Page has not been updated in more than 5 years.

Find Insight: Most logins last 20s~40s, then go to data tab.

Prioritize the Key Data shows in the Home page.

Explore: How do you define the Key Data?

Personal account
Behavior:
1. Sharing life 1-2 times a week;
2. The login and stay time are not fixed;
3. Care about the reading rate of the content and user's reading behavior;
4. I hope that the article will be promoted to more people, and rewards may be provided, but the income is not important.

Pain Points:
- Comprehensive understanding of the reading data of published articles
- More recommendations and readings

Data Demands: Posts, Reads, Likes, Collects...

Team account
Behavior:
1. The team has a division of labor, a clear topic selection system, and a detailed schedule;
2. The team has personnel specifically responsible for the operation of accounts;
3. Push for merchant promotion and care about content reading, likes and sharing data;
4. When there are activities, I will read and reply carefully, and some articles will be rewarded.

Pain Points:
- Understand the data performance of articles and accounts
- Get more traffic and exposure

Data Demands: Fans, Shares, Rewards...

Official account
Behavior:
1. A certain number of people and a duty system;
2. Don't care much about reading and fan data, but occasionally get feedback on articles;
3. Pay more attention to the public opinion orientation of promotional content and the transmission of information;
4. Mainly use the editing and publishing function without using too complicated functions.

Pain Points:
- Quickly understand article communication data
- Pay attention to public feedback

Data Demands: Reads, Shares, Interactions and Comments

Design Thinking

Summarize: Posts, Fans, Reads, Likes, Shares, Compliments, Collects, Interactions and Comments...

Diagram: Account owner outputs quality content → Data/User provides positive feedback → Platform provides quality services and guidance/balances back to Account owner.

Data Focus
Two-axis chart (Platform vs Content):
- High Platform + High Content (prioritized): Fans, Reads, Posts, Shares, Original
- Mid-range: Rewards, Likes, Comments, read by friends
- Low priority: Collects

Key data categorization:
- Content: Fans, Reads, Shares
- Platform: Posts, Original

Feedback verification
Final landing page design showing:
- Account info panel (name, original content count: 3485, total users: 5469237)
- Key metrics: Yesterday's Reads (678), Yesterday's Shares (346), Yesterday's New Followers (123)
- Feature promotions (Original & Rewards activation)
- New creation shortcuts: Image-text, Text, Video, Audio, Image, Repost, More...

PROJECT 2: WeChat Customer Service System

WeChat Customer Service
A tool that enables businesses to manage and respond to user inquiries directly within the WeChat ecosystem.

My Role
Developed a design system to support scalable, cross-team collaboration.

WeChatOS Context
- IM (Social)
- Official Account (News)
- MiniProgram (Video)
- Payment (Wallet)

Customer Service System — Problems:
- Inconsistent cross-platform experiences
- Features lagging behind business demands
- Goal: Unify Customer Service System

Library: Component Abstraction

Component hierarchy:
- Function → Post Infos
- Application → Shopping
- Date → Reminder

Component types: Dialog, Popover, Drop down...

Popover specifications:
- Text area with 20px padding on all sides
- Primary and secondary action buttons (12px and 20px spacing)
- Features: Blacklist toggle, path retrieval instructions, account selection, transfer dialog (88/100 char limit)

Library: Scenario-based product optimization

Platform: PC, Mobile → Features
Role: Manager, Customer → Authorization
Function: Q&A, Data... → Personalize

Dashboard metrics shown:
- Total sessions: 142
- Total inquiry users: 36
- Effective response rate: 86%
- Average response time: 10 min
- 15-min response rate: 90%

Mobile dashboard:
- Total sessions: 134
- Inquiry users: 134
- Effective response rate: 5.37%
- Average response time: 134
- 3-min response rate: 5.12%

Optimization: Product Inquiry Flow

48% are product inquiries

Before (complicated flow):
1. Copy URL
2. Come back to ChatBox
3. Paste
4. Typing some description
5. Send
6. Customer servicer open and check
7. Understand the description

After (simplified):
Send a rich Content Card → Purchase Rate 48% increase

Optimization: Mini Program Card Sharing

How: What you see is what you get, with a simplified workflow.

Card structure:
- Expression side: Owner, Title, Thumbnail
- Logic side: AppID, Path

Shift user perspective — "Enter page path"
- Complicated: Query Mini Program path from the backend
- Simplified: One-click copy page path

Optimization: Intuitive Adding

Customer service can add mini program cards sent by users and editing.

User inquiry method statistics:
- Text: 12%
- Image: 23%
- Cards: 65%

User flow examples (User1, User2, User3) showing various item inquiries (ASR, ItemA, ItemB, ItemC, ItemX, Complaint, Order) → matched to ProductA rich content card with "Add as quick reply" option.

Purchase Rate: 48%

Optimization: Customer service dashboard

Improve capabilities and provide Data-overview.

Results:
- Response rate: +37%
- Customer Satisfaction: +24%
- Churn Rate: -18%

Dashboards:
- PC Data Dashboard (overview with sessions, users, response metrics, trend charts)
- Mobile Data Dashboard (condensed view with key metrics)
- Customer Data panel (per-agent stats: sessions, served users, messages, user messages)
